# ASD Programming Website

Interactive versions of teacher-designed programs from the ASD (special ed) program books,
used by students on school iPads in Safari. Owner: Peter (EdTech, Portland ME elementary school).

## Hard rules
- **Web only.** No apps, installs, or student accounts. Must work in iPad Safari.
  Staff already use iPad Guided Access to keep students in Safari.
- **No student data, ever.** No names, no IDs, no student logins. Scores and history are never
  saved: the session score lives in page memory only and is wiped on Reset / reload / exit.
  Staff record data on paper data sheets. No localStorage, cookies, IndexedDB, or analytics.
- **The one exception: playlist settings.** Playlists (see below) are saved in a shared list so
  every iPad sees the same version. Only codes, program lists, and each program's settings are
  stored. Never names, scores, or history.
- **No third-party requests.** No CDNs, web fonts, analytics or trackers. Everything self-contained.
  The only outside request is the school's own playlist storage (below).

## Playlists
- A **playlist** is an anonymous code plus an ordered list of programs, each with preset settings
  (step, version, session, praise, trials, ...), plus who picks: student or staff.
- **Codes** are a random letter + number (e.g. B7, R12), generated by the playlist builder, never
  chosen by people, so they can't match initials, grade, or room. Letters I, O and K are excluded
  (I/O look like 1/0; K reads as kindergarten). The student-to-code link lives only in a paper
  staff binder.
- **Storage:** a Google Sheet plus an Apps Script web app ("Anyone" access) under Peter's school
  Google account. Reading a playlist needs nothing. Saving (builder edits, staff step bumps)
  needs a staff passcode, entered once per visit and kept only in page memory.
- Use the word "playlist" in everything user-facing (not "K-set" or "program set").

## Site structure and flow
- **Home (staff):** enter a code (letter keys, then number pad) or open a home-screen shortcut to
  one playlist. Link to the playlist builder. Footer states that nothing about a student is stored.
- **Playlist menu:**
  - Student picks: up to 6 big picture cards per screen, fixed order, no score or settings.
    Tapping a card opens a "Get ready" screen with a big Start button (student or staff taps it).
  - Staff picks: list of program cards, each with a one-line settings summary; tapping opens setup.
- **Setup (staff):** the program's setup screen, prefilled from the playlist. A change saves to the
  playlist on Start, unless the "Just for today" switch is on.
- **Program activity**, then **end screen** (calm "All done" for the student; a staff strip with %
  and the mastery reminder), then back to the playlist menu.
- **Staff button:** small, top corner of every student screen, opens on a ~1 s press-and-hold.
  Staff panel: session score, Reset, sounds on/off, end program, back to menu, edit playlist.
- **Playlist builder (teachers):** random code, who picks, add programs from the list of all
  programs (each opens its own settings), reorder/remove, save with passcode, print QR card.
- **Categories:** every program has one (Math, Literacy, Life Skills, more later). Staff screens
  show it as a colored left end on program cards plus the category word and a legend.
  Not shown on student picture cards. Colors: Math #2F6FDE, Literacy #E08A2E, Life Skills #2E9E44.
- Later idea: let staff queue several programs in a row (e.g. receptive/expressive pairs).

## Look and feel
- Color ID (`programs/color-id/`) is the visual model: warm background #F6F4EF, white cards,
  blue accent #2F6FDE, system font, large touch targets.
- Student screens: plain backgrounds, one task at a time, no animations or timers, gentle sounds
  staff can mute.

## Code structure
- Plain HTML/CSS/JS, no build step. Hosted as a static site (GitHub Pages planned; confirm

- `programs/<program-id>/index.html`: one folder per program.
- Planned: shared engine (setup screen, praise/correction, staff panel, audio), home screen,

  settings and category once; setup, builder and menu summaries are generated from that.

## Shared program conventions (from Color ID)
- Staff setup screen: version (receptive/expressive), step, session (teaching/baseline),
  praise (computer praises = default; staff praises = ding + green highlight only),
  trial count, read-aloud toggle, show-prompt-text toggle.
- Scoring: only the first response per trial counts, as + / −.
- Correction: model the correct answer, re-present; repeat until 1x independent, max 3x.
- Baseline: no prompts, no reinforcement.
- Expressive versions: student answers by voice/AAC; staff tap ✓ / ✗.
- End screen notes the mastery rule: 80%+ for 3 consecutive sessions → next step.
- Built-in iPad speech for prompts (not for phoneme/letter-sound work; use recorded audio there).
